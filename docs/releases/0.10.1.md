This release fixes the filtered copies of targets with `exclude` when an excluded path holds a very deep directory tree, and stops `--send` from writing into the mount point of a backup disk that is not mounted.

## Fixed

- Building the filtered copy failed with `Too many open files` when an excluded path held a directory tree deeper than about a thousand levels (the usual soft limit of open files is 1024, the one systemd services get), and with `File name too long` as soon as a path under it passed 4096 bytes. Either one stopped the replication of that target at that snapshot, and every later run failed the same way. rusnapshot now raises its soft limit of open files to the hard limit when it starts, and measures and removes the excluded paths through directory descriptors, so neither the length of the paths nor the depth of the tree is a limit anymore.
- With a target that is the mount point of a backup disk, `--send` with the disk unmounted found the mount point directory, empty, on the root filesystem. It forgot every replica recorded there as gone and sent full copies into that directory, where they ended up hidden under the disk once it was mounted again. When the database records replicas at a target and none of them is there, `--send` now stops with an error before sending or pruning anything. If they are gone for good (deleted by hand, or the disk was replaced), `--del --from-replica <TARGET> --id <NAME>` forgets each one.
- An I/O error while checking whether a path exists was taken for a missing path. At a local target that forgot replicas, or recorded them as pruned, while they were still there; with `--del` and `--clean` it could drop the database row of a snapshot still on disk. Those errors are now reported.
- An exclude entry that could not be looked up for a reason other than not existing was skipped, so what it was meant to keep out was sent. It now stops the filtered copy with an error.

## Safety

- The new walk never follows a symlink: every directory is opened with `O_NOFOLLOW`, symlinks are removed as links, and a directory swapped for a symlink while it runs is refused.
- Clearing the immutable and append-only attributes only opens regular files and directories. A device node is never opened, since that would reach its driver.
- The open files limit is raised for rusnapshot and the commands it runs (`btrfs`, `ssh`, `sudo`), nothing changes system wide.

## Compatibility

- No configuration, database or command line change.
- `--send` to a target where none of the recorded replicas is present now fails instead of sending. With the disk mounted nothing changes.

## Internal

- 102 tests (51 unit, 51 end-to-end), covering a tree 1500 levels deep with paths of about 13.5 KiB, an I/O error at a local target, a fifo and a symlink while clearing attributes, an exclude entry going through a file, and a target left with none of its recorded replicas.
- Tested in a container on tmpfs with an open files limit of 1024:524288, as under systemd: trees 1500 and 100000 levels deep and paths over 4096 bytes are measured and removed, and the immutable attribute tests ran as root. The standard library's `remove_dir_all`, used before, overflows its stack somewhere between 20000 and 50000 levels. Removing 200000 files took about 390 ms, against 425 ms with 0.10.0.
