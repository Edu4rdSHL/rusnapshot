This release fixes several long-standing bugs, adds `--dry-run` and machine-aware cleanup, and adds a test suite and a CI workflow that builds and publishes the release binaries.

## New

- `--dry-run` for `--create`, `--del`, `--restore` and `--clean`. Cleaning shows the exact table of snapshots that would be deleted and touches nothing.
- `--clean` now only considers snapshots created by the current machine (`-m/--machine`, defaulting to the hostname), so several machines can share one database without evicting each other's snapshots.
- Restoring to a specific directory works from the command line: `rusnapshot --restore --id <id> --to /path`.
- If a tracked snapshot was deleted outside rusnapshot, `--del`/`--clean` now remove its database row with a warning instead of failing on every run. This is skipped when the snapshots directory itself is missing (for example, not mounted) to avoid losing track of existing snapshots.
- Clearer error messages: restoring over an existing target explains what to do, a missing `btrfs` binary no longer produces a panic, and database errors include the file path.
- Release binaries for x86_64 (musl, static), i686 (musl), armv7 and aarch64 are now built and attached to releases by CI.

## Fixed

- First run with the database inside a destination directory that does not exist yet no longer fails: the directory structure is created before opening the database.
- The destination subvolume creation is now awaited and checked (it was fire-and-forget, racing against the first snapshot).
- Any failure of `btrfs` or the database now makes rusnapshot exit with a non-zero status, so systemd units and scripts can detect it. Previously most failures exited 0.
- Options given on the command line are no longer silently overridden by the configuration file. Precedence is now: command line > environment variables > configuration file.
- The `machine` value from the configuration file was stored with its TOML quotes (`"host"` instead of `host`). New snapshots store it correctly and existing rows are migrated automatically on the first run.
- All SQL queries use bound parameters, so paths or machine names containing quotes no longer break snapshot tracking.
- `btrfs subvolume snapshot` is invoked with `-r` before the positional arguments, which also works when `POSIXLY_CORRECT` is set.
- Wrong types in the configuration file (for example `keep_only = "3"`) produce a clear error instead of a panic, and unknown keys print a warning.

## Behavior changes

- `--create`, `--del`, `--restore` and `--clean` are now mutually exclusive, and `--from`/`--to` are rejected with operations that do not use them.
- `--list` combined with other operations runs last, so it shows the resulting state.
- With a configuration file, options explicitly passed on the command line now win (see Fixed above). The `RUSNAPSHOT_DB_FILE` environment variable also takes precedence over the file.
- `--clean` filters by machine. If your database has snapshots recorded under a different machine name than the current hostname, pass `-m <name>` to clean them.

## Compatibility

- Existing databases keep working: the schema is unchanged and the quoted machine migration is automatic.
- Existing configuration files and the systemd units/timers from the examples keep working unchanged.

## Internal

- New test suite: 59 tests, including end-to-end tests that run the real binary against a simulated `btrfs`, so they need no root and no btrfs filesystem.
- CI now runs clippy (deny warnings), rustfmt and the tests; a new release workflow cross-builds and publishes the binaries on every version tag.
- All dependencies updated, including toml 0.9 to 1.1. Builds with Rust 1.85+.
