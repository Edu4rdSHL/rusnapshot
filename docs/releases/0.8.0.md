This release adds `exclude` for replication targets: paths inside the snapshot that are left out of the replicas.

## New

- `exclude` per `[[replicate]]` target, and `--exclude PATH` (repeatable) together with `--target`: paths relative to the root of the source subvolume that are not sent. `btrfs send` always sends a whole subvolume, so rusnapshot sends a filtered copy instead: a read-write snapshot of the snapshot with the excluded paths deleted, then set read-only.
- Filtered copies live in `<dest_dir>/.staging/<id>/<snapshot name>`, one `<id>` per distinct exclude list. They share every extent with their snapshot and only cost metadata; `--del` and `--clean` delete them together with the snapshot. A copy left half-built is rebuilt on the next run.
- Incremental sends chain between filtered copies, so only the changes outside the excluded paths are sent. Changing the list does not force a full send.
- `--dry-run` prints how many paths and bytes would be excluded and which ones; every send reports what it excluded. `--list` shows whether a replica was sent from a filtered copy.

## Safety

- Exclude entries are validated: relative paths inside the snapshot only, no `..`, normalized and deduplicated.
- The deletion inside the copy refuses an entry whose parent resolves outside the copy (a symlink inside the snapshot pointing at the live system), removes a symlink as a link instead of following it, and uses the standard library's `remove_dir_all`, which never follows symlinks.

## Compatibility

- No database schema change. Targets without `exclude` behave exactly as in 0.7.0 and no `.staging` directory is created.

## Internal

- 90 tests (44 unit, 46 end-to-end). The simulated `btrfs` used by the tests now copies snapshot content, supports `property set` and `property get`, and sizes the send stream from the data, so the exclusion tests check the bytes sent.
- Tested against a server over ssh: a tree with 60 MiB kept and 40 MiB excluded sent 60.1 MiB in full, then 10.0 MiB incrementally after adding 10 MiB to the kept directory and 30 MiB to the excluded one; the replica contained only the kept directory and sha256 sums matched.
